# 产品方法论

## 产品原则

- [2026-10-22] 修改动作要在阅读现场完成。看、改、提意见发生在同一个界面，减少切窗口和描述位置的成本，保住心流。
- [2026-10-22] 工具负责采集精确意图，执行交给 AI。人只表达「哪里、改成什么」，定位信息由工具自动补齐。

## 设计决策记录

- [2026-10-22] 保存只用浏览器本地存储，不引入本地服务 — 挂载要足够轻，一段 JS 注入即可用。
- [2026-10-22] 改源文件走「复制修改要求 → 粘贴给 AI」 — 保持工具纯前端、通用，执行方可以是任意 AI。
- [2026-10-22] 做成独立工程，可挂到任何 HTML — 复用到所有项目，不绑定单个 Deck。

## 用户体验偏好

- 沉浸、少打断；能点一下解决的不让人描述。
- [2026-10-22] 快捷键以单字母为主（T 改字、C 批注），Alt 组合兜底中文输入法场景；同一按键再按一次退出。
- [2026-10-22] 悬停即反馈：进入模式后，鼠标移到哪里就高亮哪里能操作，不需要先点再猜。
- [2026-10-22] 选择粒度由用户掌控：单选、框选、多选三种方式并存。
- [2026-10-22] 选择判定以用户眼睛看到的为准：框选按文字实际范围和穿过的文字判断，页面盒模型等实现细节不能让操作落空。
- [2026-10-22] 批量操作不弹确认框，改为事后可撤回，保持连续操作的节奏。

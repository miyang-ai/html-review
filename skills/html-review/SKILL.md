# HTML Review

HTML Review 是一个单文件 JS 工具（`dist/html-review.js`，无外部依赖）。挂到 HTML 页面后，用户在浏览器里按 `T` 改字、按 `C` 批注，改动存在浏览器本地；点「复制修改要求」得到一段提示词和 XML 修改单，粘贴给你，由你改源文件。

仓库：https://github.com/miyang-ai/html-review

你要做的事分两类：**挂载**（第 1、2 步）和**按修改单改源文件**（第 3 步）。

## 1. 获取代码

统一放在 `~/.html-review`，所有项目共用一份：

```bash
if [ -d ~/.html-review/.git ]; then
  git -C ~/.html-review pull --ff-only
else
  git clone --depth 1 https://github.com/miyang-ai/html-review.git ~/.html-review
fi
ls ~/.html-review/dist/html-review.js
```

- `dist/` 已提交构建好的文件，**不需要** `npm install` 或构建。
- clone 失败（网络受限）时，只下载这一个文件也够用：

```bash
mkdir -p ~/.html-review/dist
curl -fL https://raw.githubusercontent.com/miyang-ai/html-review/main/dist/html-review.js -o ~/.html-review/dist/html-review.js
```

## 2. 挂载到目标 HTML

先检查目标文件是否已经挂载过（搜索 `html-review`），已有就跳过，避免重复。

按场景二选一：

| 场景 | 做法 | 写入的 script |
|---|---|---|
| 页面会移动、发给别人、或通过 http 服务访问（**默认选这个**） | 把 `~/.html-review/dist/html-review.js` 复制到 HTML 所在目录 | `<script src="html-review.js"></script>` |
| 只在本机用 `file://` 打开，希望始终用最新版 | 不复制，引用绝对路径 | `<script src="/Users/<你>/.html-review/dist/html-review.js"></script>`（写展开后的真实路径，不要写 `~`） |

插入规则：

1. 只加这一行，放在 `</body>` 前，排在页面自己的 `<script>` 之后。
2. 不改动页面其他任何内容。
3. 通过 http(s) 访问的页面不能加载 `file://` 脚本，必须用复制的方式。
4. 页面有严格 CSP（`script-src` 不允许同源以外的脚本）时，复制到同源目录。

挂载后告诉用户怎么用：

- 浏览器打开（或刷新）页面，右下角出现工具条。
- `T`（中文输入法开着时用 `Alt+T`）：改字模式，悬停高亮，点击文字直接改，`Enter` 保存，`Esc` 放弃。
- `C`（或 `Alt+C`）：批注模式，单击选中、拖拽框选、`Shift+单击` 多选，写意见后 `Enter` 保存。
- 改完点工具条「复制修改要求」，把内容粘贴回来，由你改源文件。
- 页面原有的键盘快捷键（例如 Deck 的方向键翻页）在浏览状态下照常工作，改字时会被暂时屏蔽。

可选验证（有 headless 浏览器时）：打开页面后 `window.__htmlReview` 存在，即挂载成功。

## 3. 按修改单改源文件

用户粘贴的内容长这样：

```text
请按下面的修改单修改源文件。

源文件：/abs/path/to/page.html          ← 本地文件；http 页面这里是「页面地址」，需要你找到渲染它的源文件
页面标题：…
规则：1. … 6. …

<review page="…" count="3" text_edits="2" comments="1">
  <item id="E1" type="text_edit">
    <xpath>//*[@id="deck"]/section[2]/div[1]</xpath>
    <selector>#deck > section:nth-of-type(2) .title</selector>
    <section>01 · 市场现状</section>
    <before>原文</before>
    <after>新文</after>
    <before_html><![CDATA[…]]></before_html>   ← 仅当含行内标签时出现
    <after_html><![CDATA[…]]></after_html>
  </item>
  <item id="C1" type="comment">
    <request>修改意见</request>
    <replies><reply>追加意见</reply></replies>
    <targets count="1">
      <target>
        <xpath>…</xpath><selector>…</selector><section>…</section>
        <text>目标元素的文字</text>
        <html><![CDATA[目标元素的 HTML 片段]]></html>
      </target>
    </targets>
  </item>
</review>
```

处理步骤：

1. 打开「源文件」。条目按页面阅读顺序排列，逐条处理。
2. **定位**：用 `before`（改字）或 `text` / `html`（批注）在源码里搜索原文；`xpath`、`selector`、`section` 用来在多处同文时区分。xpath 来自浏览器运行时的 DOM，可能与源码结构略有差别（JS 生成的节点、浏览器自动补的 `tbody`），三者有出入时以原文为准。
3. **改字条目**：把 `before` 改成 `after`，文字一字不差照用户写的来。有 `before_html` / `after_html` 时按 HTML 改，保留元素自身的标签、属性和行内标记。
4. **批注条目**：按 `request` 修改 `targets` 里的元素，可以改文案、结构或样式；`replies` 是后续补充，与 `request` 冲突时以最后一条为准；多个 target 时意见同时作用于这些元素。
5. 原文在源码里找不到（由 JS 或数据文件生成）时，找到生成它的数据或代码去改。
6. 只改条目涉及的内容，其余保持原样。
7. 改完逐条回报：`E1 已修改`、`C1 无法定位（原因）`、`C2 需要确认（问题）`。

用户刷新页面后，已改进源文件的改字条目会被工具自动标为「已生效」，批注由用户在修改清单里手动标为「已处理」。

## 4. 卸载

删掉 `</body>` 前那一行 `<script>`（复制方式还要删掉同目录的 `html-review.js`）。浏览器里保存的修改记录在 `localStorage`，键名 `html-review:v1:<页面路径>`，不影响页面本身。
